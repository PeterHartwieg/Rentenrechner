# Legacy EP re-estimate notice: manual-gross guard + input-status stamp (#409)

## Summary

The Produkte page offers a re-estimate when it detects Entgeltpunkte seeded by the old pre-#394 wizard. Two gaps let that offer misfire or miss. It could still appear when a manual gross pension is set, even though the projection ignores Entgeltpunkte in that case and a re-estimate would change nothing. And typing Entgeltpunkte directly on the page never recorded the value as user-entered, so the detector's user-owned check had nothing to read on that surface. This adds the manual-gross guard to the detector, stamps typed Entgeltpunkte as `entered`, and makes the combine-mode wrapper forward the status onto the workspace so both fixes hold in both modes.

## Preflight

- Invariant preserved: input-status semantics from `src/domain/inputStatus.ts` (CONTEXT.md glossary, "Input status"), "Opening a screen must never write metadata; only an explicit user edit or an explicit 'weiß ich nicht' click writes." The wrapper's no-op early-return now compares both `statutoryPension` and `inputStatus`, so opening and closing the disclosure without an edit still writes nothing, and only the typed-EP edit stamps `'entered'`.
- User-visible surface: the legacy-EP re-estimate notice on the statutory row (§ 1) of `/eingaben/produkte`. It no longer fires while a manual gross pension is in effect, and a typed Entgeltpunkte value now suppresses it on later visits.
- Regression tests: `src/features/inventory/inventoryHelpers.test.ts` (6 new detector cases) and `src/features/produkte/ProdukteEingabenPanel.test.tsx` (2 new stamp tests, one per mount).

## Tests

- `detectLegacyEpSeed`: a legacy seed plus `manualMonthlyGross: 1500` returns `{ legacy: false }` for the recorded `years` and `career` methods and for a payload with no recorded method. All three cases failed against main before the fix.
- Component tests: typing Entgeltpunkte in the GRV disclosure stamps `inputStatus['statutoryPension.currentEntgeltpunkte'] = 'entered'` in compare mode (on the assumptions returned by the change callback) and in combine mode (on the workspace patch sent to `onPatchBaseline`). Both failed against main.
- `npm run verify`: lint clean, 274 test files, 5181 tests passed (1 skipped); Worker typechecks and both Worker suites (26 + 11 tests) passed; production build and prerender succeeded. The OG images regenerated by the build were discarded and are not committed.

## Review round 1

Manual mode uses `manualMonthlyGross !== null`, including an explicit zero. The detector now uses that same guard, and its comments explicitly cover zero. Added zero-value regression cases for recorded `years` and `career` methods and the absent-method branch, retaining all three 1500 cases. The three new cases failed before the guard fix; full verification now passes.
